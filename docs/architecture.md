# Architecture

`src/wasm.rs` validates the binary with wasmparser and builds typed, structured function bodies. It retains imports, signatures, globals, the initial function table and active data segments. Unsupported module features return contextual compiler errors.

`src/optimize.rs` first inlines small straight-line memory wrappers, exposing constant pointer arguments to the backend. Candidates have no private locals, nested calls or branches, at most 16 instructions and four arguments. Fresh caller locals receive arguments in stack order; a 128-instruction budget per caller limits expansion. Integer constants propagate through locals and through structured regions that do not change them. Loop-entry facts discard every local written anywhere in the loop, so a first-iteration constant is never incorrectly reused after a backedge.

`src/backend.rs` walks reachable functions into a small value IR: constants, materialized registers and deferred expressions. It emits Minecraft command functions directly from structured control flow. Blocks and loops have explicit continuation functions; branches end with `return run function`. Stack joins use parallel copies, eliminate self-copies and save only values endangered by another copy. Function call graph cycles select the functions needing saved frames; ordinary acyclic calls do not pay recursive frame-save costs.

i32 registers use scoreboard holders. Basic-block interval analysis proves which arithmetic intermediates fit signed i32. Safe trees become a single native integer provider, including masks, shifts, division, addition and multiplication. Unbounded wrapping hashes/PRNGs stay on scoreboards because integer providers report overflow instead of wrapping. Byte/halfword loads contribute bounded ranges. Constant propagation and specialized wide operations remain in use; i64 is a pair of i32 words with limb arithmetic and restoring division.

Comparisons write their boolean destination directly. Signed integer comparisons use scoreboard predicates; unsigned comparisons split by operand signs. Float predicates contain the arithmetic expressions being compared, avoiding copies into temporary float storage. Calls only freeze values needing a snapshot: immutable constants and private caller registers are reused. Recursive entry/exit already saves and restores those registers.

Floats live as NBT floats. Deferred expression trees become native float providers and `data modify ... set compute default float`, reducing command dispatch and intermediate storage. f64 values deliberately share this f32 representation. Native providers also handle common imported math operations. This favors game-style finite arithmetic over IEEE corner-case emulation.

Linear memory is sparse little-endian 32-bit words. The default backend uses fake holders `#m<word-index>` in a separate `namespace_mem` scoreboard objective; initialization resets only that objective. Missing words are zero. `--nbt-memory` retains the previous compound representation, `namespace:mem w.a<word-index>`. Static loads use the corresponding score or storage provider, so expression batching works with both layouts. Constant-address integer loads in modules without f32 become deferred provider leaves: multiple loads and arithmetic can execute in one command. Before a possible write, pending reads are materialized to preserve their values. Load forwarding reuses values already read or stored, including across branches/loops when conservative region effects prove their memory and address/value registers unchanged. Disjoint constant-address stores preserve unrelated cached values. Unknown calls, possible aliasing writes, bulk writes and changed dependencies invalidate facts; stack-join register dependencies are discarded. Each emitted branch gets its own analysis state. This is conservative forwarding, not full SSA memory promotion or general dead-store elimination.

Dynamic addresses use small function macros. A dynamic word read uses `return run scoreboard players get #m$(p) namespace_mem` by default, or `return run data get storage ... w.a$(p)` with NBT memory. Both avoid a substituted number-provider expression. The caller captures zero on a missing word; differential tests include fresh unwritten dynamic addresses. Each Wasm function receives private copies of its reachable small memory helpers, giving its address macros separate caches without adding a runtime selector or extra commands. This grows static pack size; bulk/host paths and arithmetic helpers remain shared. Byte RMW arithmetic is one static, pre-parsed integer provider per byte lane; only address and lane selection use macros. The four-way byte-lane macros remain shared because all four variants fit the cache. The top byte uses signed reconstruction so the expression never overflows i32. Aligned runs in memory.copy/fill use 32-bit word chunks; byte heads/tails and differently aligned copies retain a byte fallback. Overlapping copies retain memmove direction. There are no memory blocks, entities, jukeboxes, chunk scans or initial zero-filled megabyte arrays.

Optimized modules using f32 keep each aligned float word in one NBT record: `namespace:fmem w.a<word-index> = {v:<float>,d:1b}`. The `d` field exists only while the canonical bits are stale. A float store updates the typed value without encoding IEEE bits. A later integer/byte read materializes that word's bits on demand and removes `d`. A full-word integer overwrite removes the whole record in one command, while a partial write first materializes and then invalidates it. Unaligned float accesses use the canonical representation. Float loads reuse typed values; f64 remains approximate f32 arithmetic. External raw memory inspection may observe stale canonical bits while a float word is dirty; Wasm accesses are coherent. Metadata identifies this layout as `word-record-v1`; initialization resets it and removes the old separate dirty-map storage.

Aligned whole-word copies transfer the entire cache record only if the source has one. If the source has no record, they remove the destination record only when it exists. Copying a clean source over a dirty destination clears the old dirty bit because the compound is replaced, not merged. Empty-to-empty copies perform no NBT mutation. The general aligned loop and guarded static copies use these same two conditional commands instead of four unconditional cache mutations per word. The raw canonical word still copies separately, preserving arbitrary integer bytes alongside lazy float values.

`--word-buffer` is an experimental one-word integer write-back buffer for optimized modules without f32. It coalesces adjacent byte writes, forwards reads and flushes before conflicting accesses and on export exit. It is disabled by default: it slowed the measured Celeste workload, and its bookkeeping did not give a robust Serde improvement. This is separate from the default compiler's basic-block load forwarding and lazy float memory.

Small command helpers are inlined only at unconditional call sites that ignore the command result. Macros, `return`, conditional calls and result-capturing calls are excluded. Aligned 32-bit accesses use a shorter path; unaligned accesses retain their byte fallback. Constant-address f32 accesses use static cache paths.

A full-function structural matcher recognizes the included four-byte-unrolled scalar forward-copy loop. It checks the signature, locals, every instruction and structured branch against `src/patterns/forward-copy.wasm`, with readable WAT alongside it. It uses bulk memory copy only where memmove ordering is equivalent; overlapping `dst > src` ranges preserve the original byte-propagating loop. Other loop shapes remain unchanged. An aligned forward-copy loop hoists address division and copies typed float cache entries with their dirty flags, avoiding float encode/decode work during whole-record copies.

`--copy-profile` accepts an array of `{src,dst,len}` records. Each compiled fast path has exact guards for all three values; all other calls fall through. The compiler unrolls canonical word copies into direct static commands and copies float cache state coherently. Byte tails use the ordinary byte path. The write buffer flushes and invalidates before a specialized copy. Profiles require aligned forward ranges of 1..4096 bytes inside the supported signed address range; at most 256 distinct entries and 262144 total bytes cap code growth. These are optional performance hints, not assertions that other addresses cannot occur. The measured Celeste profiles contain 28 entries collected during 180 replay frames.

`src/runtime.rs` generates helpers for memory, integer bit operations, wide arithmetic, numeric conversions, and command-string handling. Runtime helper reachability is pruned after code generation. The compiler checks that generated static function references resolve. Macro dispatch retains the matching family of helpers conservatively.

Pack writing refuses a nonempty directory without a `wasmcompute.json` marker. Recompilation replaces generated paths but currently leaves obsolete files from earlier compilations in place; use a fresh output directory for release packs and pack-size comparisons. Never treat `wasmcompute.json` as a sandbox boundary against hostile paths or code. The intended input is trusted application Wasm, and a command binding intentionally has Minecraft function authority.

## Snapshot features verified in a real server

The target is pinned rather than inferred from a marketing version name:

- [26.3 snapshot 10](https://www.minecraft.net/en-us/article/minecraft-26-3-snapshot-10) introduced command-oriented compute facilities.
- [26.3 pre-release 1](https://www.minecraft.net/en-us/article/minecraft-26-3-pre-release-1) changed integer and float provider handling.
- [26.3 pre-release 3](https://www.minecraft.net/en-us/article/minecraft-26-3-pre-release-3) updated float modulo behavior and the pack format.
- [26.3 release candidate 1](https://www.minecraft.net/en-us/article/minecraft-26-3-release-candidate-1) is the measured target.

Working target syntax includes `compute default integer <provider>` and `data modify storage ... set compute default float <provider>`. The RC's inline float predicate uses a `type:float_value_check` discriminator. Actual-server tests caught the difference from earlier syntax. Function macros and `return run` provide dynamic addressing, typed command templates, and branch termination.

The output intentionally does not promise compatibility with 1.21 or an untested later snapshot. A target-syntax change requires backend changes and a new real-server validation run.
